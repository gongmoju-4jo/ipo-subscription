# 유비쿼터스 언어

> 팀 전원이 대화, 문서, 코드(클래스, 필드, 토픽, 상태값)에서 같은 단어를 쓰기 위한 사전입니다.

## 1. 핵심 개념

| 한글      | 코드명 | 뜻 | 쓰지 않을 말 |
|---------| --- | --- | --- |
| 공모주 (종목) | `Ipo` | 상장하면서 일반에 새로 파는 주식. 공모가, 물량, 청약 기간을 가짐 | 상품, 주식 |
| 공모가     | `offerPrice` | 수요예측으로 확정된 1주 가격 | 가격, 단가 |
| 일반청약 물량 | `retailQuantity` | 우리 증권사가 일반투자자에게 배정할 총 주식 수 | 재고, 수량 |
| 청약      | `Subscription` | 투자자가 공모주를 사겠다고 신청한 1건 | 주문, 신청 |
| 청약 수량   | `requestedQuantity` | 투자자가 신청한 주식 수 | 주문 수량 |
| 청약 금액   | `subscriptionAmount` | 청약 수량 x 공모가 | 주문 금액 |
| 예수금     | `cashBalance` | 계좌에서 자유롭게 쓸 수 있는 돈 (출금 가능액) | 잔액, 현금 |
| 청약증거금   | `marginBalance` | 청약에 잡혀 있는 증거금의 합계 | 묶인 금액 |
| 증거금     | `Margin` | 청약 금액 x 증거금률. 청약 1건당 1개 | 보증금, 예치금 |
| 증거금률    | `marginRate` | 청약 금액 중 증거금으로 맡기는 비율. **우리 프로젝트는 100%** (실제 공모주는 보통 50%. 100%면 배정 대금이 증거금을 넘지 않아 추가 납입이 필요 없음) | - |
| 증거금 인출  | 상태 `PENDING` | 예수금에서 청약증거금으로 옮김 (2단계 이체의 pending) | 묶기, 홀드, 차감 |
| 정산      | 상태 `POSTED` | 배정 대금만큼 청약증거금에서 실제로 차감, 나머지는 예수금으로 환불 (`postedAmount`) | 결제 |
| 증거금 해제  | 상태 `VOIDED` | 청약증거금 전액을 예수금으로 되돌림 (확정 실패 보상, 취소, 0주 배정) | 풀기, 환불, 취소 |
| 원장      | `LedgerEntry` | 돈이 움직일 때마다 남기는 기록 (추가만, 수정 없음) | 로그, 이력 |
| 최소 청약 수량 | `minQuantity` | 종목별 최소 신청 수량. 균등배정 자격 기준 | - |
| 청약 한도   | `maxQuantity` | 1인당 최대 신청 수량 | - |
| 청약 기간   | `subscriptionStartAt`, `subscriptionEndAt` | 청약 받는 시작/마감 시각. 마감 판단은 게이트웨이 도착 시각 기준 | 판매 기간 |
| 마감      | `close` | 청약 기간 종료. 이후 신청, 취소 불가 | 종료 |
| 청약 취소   | `cancel` | 마감 전 투자자가 청약을 철회 → 증거금 해제(`VOIDED`) (SHOULD) | 환불 |
| 계좌      | `Account` | 투자자 명의의 증권 계좌 (가상 계좌). 1인 여러 개 가능 | 통장 |
| 계좌번호    | `accountNumber` (DB `account_number`) | 화면에 보여주는 계좌 번호. 개설할 때 만든 숫자 12자리 난수. 계좌 서비스만 가지고, 다른 서비스, API, 이벤트는 계속 `accountId`로 참조 | 계좌 ID와 혼용 |

| 배정 수량 | `allocatedQuantity` | 청약 1건에 배정된 주식 수 (균등 + 비례, 0주 가능) | 당첨 수량 |
| 배정 대금 | `allocatedAmount` | 배정 수량 x 공모가 | 결제 금액 |

## 4. 청약 상태값

| 상태 | 코드명 | 뜻                                               |
| --- | --- |-------------------------------------------------|
| 접수됨 | `PENDING` | API가 받았고 SAGA 진행 중 (202 응답 시점)                  |
| 확정 | `CONFIRMED` | 증거금 인출(`PENDING`) 완료, 청약 유효                     |
| 거절 | `REJECTED` | 잔액 부족, 이중청약 등으로 증거금 인출 전에 실패. 보상 없음, 재청약 가능     |
| 보상 중 | `COMPENSATING` | 증거금은 인출됐는데 청약 확정에 실패해서 증거금 해제(`VOIDED`)를 요청한 상태 |
| 취소 요청 | `CANCEL_REQUESTED` | 투자자가 취소 요청, 처리 중 (SHOULD)                       |
| 취소됨 | `CANCELLED` | 취소 또는 확정 실패 보상 완료, 증거금 해제(`VOIDED`) 완료, 재청약 가능  |
| 배정 완료 | `ALLOCATED` | 마감 후 배정 수량 확정                                   |
| 환불 완료 | `REFUNDED` | 정산과 환불까지 끝남 (0주면 증거금 전액 해제)                     |

## 5. 공모주(종목) 상태값

| 상태 | 코드명 | 뜻 |
| --- | --- | --- |
| 청약 중 | `OPEN` | 청약 시작 ~ 마감 시각 |
| 마감 | `CLOSED` | 마감 시각 지남. 접수 토픽에 남은 메시지(Consumer 랙 0)와 처리 중인 청약(`PENDING` 0)이 없을 때 마감 이벤트 발행 |
| 배정 완료 | `ALLOCATED` | 배정 확정, 정산과 환불 진행 |

> 배정이 진행 중인지는 공모주 상태가 아니라 배정 서비스의 `allocation_round` 상태(`RUNNING`, `DONE`, `FAILED`)로 봅니다.

## 8. 헷갈리기 쉬운 것

- **해제 vs 환불**: 해제(`VOIDED`)는 청약이 유효하지 않게 됐을 때 증거금 전액을 예수금으로 되돌리는 것 (확정 실패, 취소, 0주 배정). 환불은 배정 후 정산(`POSTED`)하고 남은 금액을 예수금으로 돌려주는 것
- **인출(확보) vs 정산**: 인출(`PENDING`)는 예수금 → 청약증거금 이동 (아직 내 돈, 쓸 수만 없음). 정산(`POSTED`)은 배정 대금만큼 청약증거금에서 실제로 빠짐 (공모주 대금으로 나감)
- **예수금 vs 청약증거금**: 둘 다 같은 계좌 안의 돈. 예수금(`cashBalance`)은 쓸 수 있고, 청약증거금(`marginBalance`)은 청약에 잡혀 있음
- **인출 vs 홀드**: 홀드는 돈을 그 자리에 두고 "묶임" 표시만 하는 방식(카드 승인). 우리는 증권사 청약처럼 청약증거금 칸으로 실제로 옮기는 방식이라 "홀드"라는 말은 쓰지 않음
- **청약 상태 `PENDING` vs 증거금 상태 `PENDING`**: 청약 `PENDING`은 "접수됐고 처리 중", 증거금 `PENDING`은 "인출돼서 정산이나 해제를 기다리는 중". 둘 다 "아직 안 끝남"이지만 다른 테이블의 상태값
- **거절(`REJECTED`) vs 보상(`COMPENSATING` → `CANCELLED`)**: 거절은 돈을 옮기기 전에 실패해서 되돌릴 것이 없음. 보상은 돈을 옮긴 뒤에 실패해서 해제가 필요함
- **일반청약 물량(`retailQuantity`) vs 배정 수량(`allocatedQuantity`)**: 일반청약 물량은 공모주(`ipo`)에 처음부터 정해진 "일반투자자에게 나눠줄 전체 주식 수"(예: 100,000주). 배정 수량은 마감 후 청약 1건이 실제로 받은 주식 수(예: 3주). 청약 미달이 아니면 모든 청약의 배정 수량 합 = 일반청약 물량. `allotted_quantity`처럼 둘 중 무엇인지 모호한 이름은 쓰지 않음
- **공모주 `ALLOCATED` vs 청약 `ALLOCATED`**: 같은 이름이지만 공모주 상태는 "이 종목의 배정이 끝남", 청약 상태는 "이 청약의 배정 수량이 정해짐"
- **청약 vs 주문**: 일반 주식 매매(주문)와 다름. 신청한 만큼 못 받고 나눠 받음
